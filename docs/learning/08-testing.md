## 8.1. Зачем тесты и как их запускать

**Что изучаем.** Виды тестов (unit, integration, end-to-end), что они
проверяют и сколько стоят. Встроенный `node:test` и `node:assert`.

**Задание.** Написать первый тест, добавить скрипт `test` в
`server/package.json`, увидеть падающий и проходящий тест.

**Критерии готовности.** `npm test` в папке `server` запускает тесты.

**Вопросы для самопроверки.**

- Чем unit-тест отличается от integration-теста?
- Почему важно увидеть, как тест падает?

**Документация.**

- [Node.js: Test runner](https://nodejs.org/api/test.html)
- [Node.js: Assert](https://nodejs.org/api/assert.html)

## 8.2. Unit-тесты

**Что изучаем.** Тестирование чистых функций: валидация URL, конфигурация,
классификация ошибок. Граничные случаи.

**Задание.** Покрыть тестами `isValidUrl` и чтение конфигурации, включая
некорректные значения.

**Критерии готовности.** Тесты проходят и падают при намеренной поломке кода.

**Вопросы для самопроверки.**

- Как выбрать набор тестовых случаев?

## 8.3. Тестирование функции проверки сайта

**Что изучаем.** Как тестировать код, который ходит в сеть, не завися от
интернета: локальный тестовый HTTP-сервер (`node:http`) с нужными ответами,
задержками и ошибками.

**Задание.** Проверить сценарии: 200, 404, 500, редирект, таймаут,
закрытый порт.

**Критерии готовности.** Тесты не обращаются во внешний интернет и проходят
стабильно.

**Вопросы для самопроверки.**

- Почему тест, зависящий от `example.com`, — плохой тест?

**Документация.**

- [Node.js: http.createServer](https://nodejs.org/api/http.html#httpcreateserveroptions-requestlistener)

## 8.4. Тестирование API

**Что изучаем.** `app.inject()` — отправка запросов в Fastify без открытия
порта (здесь пригодится `buildApp` из этапа 5).

**Задание.** Протестировать `/api/health`, `/api/check` (валидный и
невалидный ввод), формат ошибок.

**Критерии готовности.** Покрыты успешные и ошибочные ответы каждого маршрута.

**Вопросы для самопроверки.**

- Чем `inject` отличается от реального HTTP-запроса?

**Документация.**

- [Fastify: Testing](https://fastify.dev/docs/latest/Guides/Testing/)

## 8.5. Integration-тесты с базой данных

**Что изучаем.** Отдельная тестовая БД, подготовка и очистка данных между
тестами, изоляция.

**Задание.** Протестировать API сайтов (добавление, список, удаление) на
настоящей тестовой БД.

**Критерии готовности.** Тесты не зависят от порядка запуска и не трогают
рабочую БД.

**Вопросы для самопроверки.**

- Почему тесты не должны зависеть друг от друга?

## 8.6. Логирование

**Что изучаем.** Встроенный в Fastify логгер (pino), уровни логов,
структурированные логи, что логировать, а что нельзя (секреты, персональные
данные).

**Задание.** Пройтись по коду и добавить логи для важных событий: старт,
ошибки проверок, работа планировщика. Уровень логов — из конфигурации.

**Критерии готовности.** По логам можно понять, что происходило с сервером.

**Вопросы для самопроверки.**

- Чем `info` отличается от `error` и `debug`?
- Почему логи в JSON удобнее для production?

**Документация.**

- [Fastify: Logging](https://fastify.dev/docs/latest/Reference/Logging/)
