## 7.1. Таймеры в Node.js

**Что изучаем.** `setTimeout`, `setInterval`, их отмена. Почему `setInterval`
опасен для долгих асинхронных задач (наложение запусков) и почему часто
используют «рекурсивный» `setTimeout`.

**Задание.** В playground показать наложение запусков при `setInterval` с
задачей дольше интервала и исправить через `setTimeout`.

**Критерии готовности.** Наложение воспроизведено и устранено.

**Вопросы для самопроверки.**

- Что случится, если проверка всех сайтов идёт дольше интервала?
- Как остановить таймер?

**Документация.**

- [Node.js: Timers](https://nodejs.org/api/timers.html)

## 7.2. Планировщик проверок

**Что изучаем.** Фоновая задача в том же процессе, что и HTTP-сервер.
Ограничение параллельности: не проверять 1000 сайтов одновременно.

**Задание.** Создать модуль планировщика, который через интервал из
конфигурации проверяет все сайты из БД (используя сервис из этапа 5) и
сохраняет результаты.

**Критерии готовности.** Проверки идут автоматически; одновременно
выполняется не больше N проверок.

**Вопросы для самопроверки.**

- Почему опасно запускать все проверки разом?
- Почему планировщик переиспользует тот же сервис, что и `POST /api/check`?

## 7.3. Сетевые ошибки и ограничения

**Что изучаем.** Классификация ошибок (DNS, соединение, TLS, таймаут),
сохранение причины в истории. Что делать, если упала сама проверка
(ошибка в нашем коде), чтобы планировщик не остановился.

**Задание.** Убедиться, что ни одна ошибка проверки не останавливает
планировщик, и что причина недоступности сохраняется.

**Критерии готовности.** Планировщик продолжает работу после любых ошибок
отдельных проверок.

**Вопросы для самопроверки.**

- Чем ошибка проверяемого сайта отличается от ошибки в нашем коде?

## 7.4. История проверок в API

**Что изучаем.** Выборка истории с ограничением (`LIMIT`), пагинация,
индексы для ускорения запросов.

**Задание.** `GET /api/sites/:id/checks?limit=N` — последние проверки сайта.
Добавить индекс и посмотреть план запроса через `EXPLAIN`.

**Критерии готовности.** Запрос возвращает историю в правильном порядке.

**Вопросы для самопроверки.**

- Зачем ограничивать количество возвращаемых записей?
- Что такое индекс, и когда он помогает?

**Документация.**

- [PostgreSQL: Indexes](https://www.postgresql.org/docs/current/indexes.html)
- [PostgreSQL: Using EXPLAIN](https://www.postgresql.org/docs/current/using-explain.html)

## 7.5. Отображение последних результатов

**Что изучаем.** Обновление данных на клиенте: периодический опрос сервера
(polling) с `useEffect`, очистка таймера при размонтировании.

**Задание.** Список сайтов обновляется сам; для каждого видны последние
результаты.

**Критерии готовности.** Интерфейс показывает свежие данные без перезагрузки
страницы; таймеры не «утекают».

**Вопросы для самопроверки.**

- Зачем `useEffect` возвращает функцию очистки?

**Документация.**

- [React: Synchronizing with Effects](https://react.dev/learn/synchronizing-with-effects)

## 7.6. Корректная остановка приложения

**Что изучаем.** Сигналы `SIGINT`/`SIGTERM`, graceful shutdown: перестать
принимать запросы, дождаться текущих проверок, остановить таймеры, закрыть
соединения с БД.

**Задание.** Реализовать корректную остановку сервера.

**Критерии готовности.** По Ctrl+C сервер завершается без ошибок и
незавершённых операций.

**Вопросы для самопроверки.**

- Что может пойти не так, если процесс убить посреди записи в БД?

**Документация.**

- [Node.js: Signal events](https://nodejs.org/api/process.html#signal-events)
- [Fastify: close](https://fastify.dev/docs/latest/Reference/Server/#close)
