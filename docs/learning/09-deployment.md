## 9.1. Development и production

**Что изучаем.** Чем отличается запуск в разработке и в production: сборка
фронтенда (статические файлы), компиляция сервера, `NODE_ENV`, переменные
окружения на сервере.

**Задание.** Собрать клиент и сервер, запустить production-версию локально,
разобрать содержимое `client/dist` и `server/dist`.

**Критерии готовности.** Production-сборка запускается и работает локально.

**Вопросы для самопроверки.**

- Что делает Vite при сборке?
- Почему в production не используется `node --watch`?

**Документация.**

- [Vite: Building for Production](https://vite.dev/guide/build)
- [Vite: Env Variables and Modes](https://vite.dev/guide/env-and-mode)

## 9.2. Один сервер для API и frontend

**Что изучаем.** В production нет прокси Vite. Варианты: Fastify раздаёт
собранный фронтенд сам или стоит за reverse proxy. Как это связано с CORS
из этапа 4.

**Задание.** Выбрать вариант и настроить так, чтобы клиент и API работали
с одного origin.

**Критерии готовности.** Production-версия открывается в браузере, проверка
сайта работает.

**Вопросы для самопроверки.**

- Почему при одном origin не нужен CORS?

## 9.3. Безопасность

**Что изучаем.** Особенно важно для StatusHub — **SSRF**: сервис делает
запросы на URL от пользователя и может быть использован для доступа к
внутренней сети. Также: ограничение частоты запросов, валидация, HTTPS,
секреты, заголовки безопасности.

**Задание.** Запретить проверку внутренних адресов (localhost, приватные
сети), добавить ограничение частоты запросов, проверить остальные пункты.

**Критерии готовности.** Запрос на проверку `http://127.0.0.1` или
`http://169.254.169.254` отклоняется.

**Вопросы для самопроверки.**

- Почему проверки строки URL недостаточно для защиты от SSRF (DNS, редиректы)?
- Зачем ограничивать частоту запросов?

**Документация.**

- [OWASP: SSRF Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)
- [OWASP Top Ten](https://owasp.org/www-project-top-ten/)

## 9.4. Основы Docker

**Что изучаем.** Образ и контейнер, Dockerfile, многоэтапная сборка,
Docker Compose для приложения и PostgreSQL.

**Задание.** Написать Dockerfile для приложения и `compose.yaml` с БД;
запустить всё одной командой.

**Критерии готовности.** `docker compose up` поднимает рабочий StatusHub.

**Вопросы для самопроверки.**

- Чем образ отличается от контейнера?
- Где хранятся данные БД, если контейнер пересоздать?

**Документация.**

- [Docker: Get started](https://docs.docker.com/get-started/)
- [Docker Compose](https://docs.docker.com/compose/)

## 9.5. Деплой

**Что изучаем.** Варианты размещения (VPS, PaaS), переменные окружения на
сервере, домен и HTTPS, проверка работоспособности через `/api/health`.

**Задание.** Развернуть StatusHub и проверить работу публичного сервиса.

**Критерии готовности.** Сервис доступен по публичному адресу через HTTPS,
данные сохраняются после перезапуска.

**Вопросы для самопроверки.**

- Как обновить приложение на сервере без потери данных?
- Как узнать, что сервис упал?
