## Цель проекта

StatusHub — небольшой сервис для проверки доступности веб-сайтов.

Пользователь добавляет URL сайта, запускает проверку и видит:

- доступен ли сайт;
- HTTP-статус ответа;
- время ответа сервера.

Проект учебный: задача не только получить работающий продукт, но и разобраться,
как устроен full-stack на практике.

## Технологический стек

| Часть    | Технологии                    |
| -------- | ----------------------------- |
| Frontend | React, TypeScript, Vite       |
| Backend  | Node.js, TypeScript, Fastify  |

На старте **не используем**: базы данных, Docker, Redis, очереди задач,
авторизацию. Новая технология появляется только тогда, когда без неё
неудобно решать текущую задачу, и сначала объясняется, зачем она нужна.

Состояние проекта на старте:

- `server/src/index.ts` — Fastify-сервер с маршрутом `GET /health`;
- `client/src/App.tsx` — заготовка React-приложения;
- клиент и сервер пока не связаны.

## Принципы обучения

1. Двигаемся небольшими шагами.
2. Не переходим к следующей теме, пока не понятна предыдущая.
3. Сначала разбираемся в принципе работы, затем пишем код.
4. Не добавляем абстракции и сложность без необходимости.
5. Основную логику пишет разработчик; ИИ-агент — наставник, а не исполнитель.
6. После каждой задачи проверяем результат и разбираем написанный код.
7. Не пытаемся реализовать весь проект за один раз.

## Как проходит одна задача

Каждая задача в файлах этапов описана по единому шаблону:

| Раздел                     | Что содержит                                        |
| -------------------------- | --------------------------------------------------- |
| **Что изучаем**            | Концепция простыми словами и зачем она нужна        |
| **Задание**                | Что сделать руками                                  |
| **Критерии готовности**    | Проверяемые признаки того, что задача выполнена     |
| **Вопросы для самопроверки** | На них нужно уметь ответить своими словами        |
| **Документация**           | Ссылки на официальные источники                     |

Цикл работы над задачей:

1. **Объяснение.** Агент объясняет новую концепцию простыми словами,
   разработчик задаёт вопросы, пока не станет понятно.
2. **Реализация.** Разработчик пишет код сам. Если застрял — просит
   подсказку, а не готовое решение (см. [уровни подсказок](#уровни-подсказок)).
3. **Проверка.** Запускаем код и сверяемся с критериями готовности.
4. **Разбор.** Агент делает ревью: что хорошо, что можно улучшить, почему.
   Разработчик объясняет, как работает его код.
5. **Самопроверка.** Отвечаем на вопросы задачи без подсказок. Если ответ
   не получается — возвращаемся к объяснению.
6. **Фиксация.** Отмечаем задачу `[x]` в файле этапа и пишем короткую запись
   в [журнал](journal.md).

Если задача оказалась слишком большой — делим её на подзадачи (`1.3a`, `1.3b`)
прямо в файле этапа.

### Уровни подсказок

Когда что-то не получается, просим помощь по нарастающей:

1. **Наводящий вопрос** — «на что стоит посмотреть?»
2. **Направление** — какая функция, тема или раздел документации нужны.
3. **Псевдокод или фрагмент** — схема решения без готового кода целиком.
4. **Разбор готового варианта** — только если первые три уровня не помогли;
   после этого код нужно переписать самостоятельно по памяти.

## Роль ИИ-агента

Агент работает как наставник. Правила для него зафиксированы в
[AGENTS.md](../../AGENTS.md) в корне репозитория:

- не выдаёт сразу весь код готового решения;
- перед реализацией объясняет новую концепцию;
- после реализации разбирает написанный код;
- предупреждает, если следующий шаг требует новой технологии, и объясняет зачем;
- отмечает завершённые задачи в документации.

## Где писать учебный код

- **`server/playground/`** — эксперименты и упражнения этапов 1–2, которые не
  входят в продукт. Запуск: `node playground/<файл>.ts` из папки `server`.
  Проверка типов: `npx tsc -p playground` из папки `server`.
- **`server/src/`** и **`client/src/`** — код самого StatusHub.

Node.js 22.18+ выполняет TypeScript напрямую, просто удаляя типы. Поэтому в
проекте включён `erasableSyntaxOnly`: нельзя использовать `enum`, `namespace`
и параметры-свойства конструктора. Это не ограничение, а повод использовать
union-типы — подробнее в [этапе 1](01-typescript.md).

## Критерий успешного завершения

В результате получается небольшой, но полноценный full-stack проект StatusHub,
а разработчик понимает:

- как работает TypeScript;
- как устроен Node.js;
- как создавать HTTP API;
- как frontend взаимодействует с backend;
- как организовывать backend-архитектуру;
- как работать с базой данных;
- как тестировать и разворачивать приложение.
