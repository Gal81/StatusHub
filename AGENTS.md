# StatusHub — инструкции для ИИ-агентов

Это учебный проект. Агент здесь — **автор кода и объясняющий**, разработчик —
читает, разбирается и подтверждает. Главный приоритет — понимание
разработчика, а не скорость разработки.

Учебный процесс, этапы и задачи: [docs/learning/README.md](docs/learning/README.md).

## Как работать

- Перед началом сессии смотреть, какая задача текущая: первая неотмеченная
  `[ ]` в файле этапа со статусом 🟡 (или первого ⬜, если 🟡 нет).
- Двигаться по учебному плану **маленькими шагами**. Задачу этапа разбивать
  на 2–4 шага; один шаг — одна идея.
- **Код пишет агент.** Объяснение «что это и зачем» — прямо рядом с кодом,
  в комментариях: простыми словами, с причиной, а не пересказом синтаксиса.
- После шага: кратко сказать в чате, что добавлено и на что посмотреть,
  как запустить/проверить (и самому запустить проверку). Затем **ждать
  подтверждения** разработчика. Без подтверждения к следующему шагу
  не переходить.
- Если у разработчика вопросы — отвечать и при необходимости дополнять
  комментарии в коде, а не только писать в чат.
- Вопросы для самопроверки из задачи разбирать в конце задачи: агент даёт
  ответ в комментариях кода, разработчик может предложить свой вариант.
- Не добавлять библиотеки, абстракции и инструменты без необходимости. Если
  следующий шаг требует новой технологии — сначала объяснить, зачем она нужна,
  и согласовать.
- Не забегать вперёд по этапам: не использовать в решениях то, что ещё не
  изучено, без объяснения.

## Отметки о прогрессе

После завершения задачи (с согласия разработчика):

1. Отметить задачу `[x]` в списке задач файла этапа.
2. Обновить статус этапа в таблице в `docs/learning/README.md`
   (⬜ → 🟡 при первой начатой задаче, 🟡 → ✅ когда все задачи готовы).
3. Предложить разработчику сделать запись в `docs/learning/journal.md`
   (пишет сам; агент может помочь сформулировать).

## Технические особенности

- Сервер запускает TypeScript напрямую через Node.js 22.18+ (type stripping).
  Включены `erasableSyntaxOnly` и `verbatimModuleSyntax`: нельзя `enum`,
  `namespace`, parameter properties; типы импортируются через `import type`.
- Учебные упражнения этапов 1–2 — в `server/playground/`.
- Проверки: `npm run typecheck --prefix server`, `npm run lint --prefix client`,
  `npm run build --prefix client`.

## Git

- Коммитить и пушить сразу в `master`. Ветки и pull request'ы не создавать —
  проект учебный, работает один разработчик.
- После каждого завершённого урока (задача отмечена `[x]`) — коммитить и
  пушить его код вместе с отметками о прогрессе. В остальных случаях —
  только по просьбе разработчика.
